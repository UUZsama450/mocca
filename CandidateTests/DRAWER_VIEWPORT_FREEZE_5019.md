# 5019：侧边栏运动期间合并正文视口重复刷新

## 目的与基线

这是网页 GPT 所提“拖动时暂停正文多余工作”的一项独立实验，基线为 5018 / `7c74a36`。它只验证原生正文视口重复通知的合并，不代表已经完成网页建议中的所有冻结项目，也不代表确认卡顿根因。

5019 默认开启；启动参数 `-disableDrawerViewportFreeze` 可在同一候选中关闭该实验。正式退回点是单独保存并通过编译的 5018，手机未被安装或覆盖。

## 实现

- RootView 只在手势接管、自动收尾开始/取消/完成和根视图离开时通知暂停状态，新增 5 处调用；不增加逐帧状态写入。
- 手指与收尾分别持有暂停状态。手指交给收尾、收尾被手指重新接管时，仍有一个持有者便不解除暂停。
- 每个 GlyphSelectableTextView 在真实视口检查后记录 window、原生滚动宿主、正文 bounds/frame、滚动 bounds/offset/contentSize/insets 和本次交互代次。
- 只有这些信息完全相同的 `outer-content-offset` / `outer-bounds` 通知才暂缓。真实滚动、内容大小/布局/文字变化、宿主更换仍检查并刷新。
- 暂缓前把现有可见段落的横向绘制范围扩展到正文宽度，保留原有纵向 720pt overscan。关闭时逐渐露出的文字因此已有绘制范围；不改变文字容器宽度和换行规则。
- 结束时清空弱引用待处理集合，每个仍存活的参与视图检查一次。离窗移除登记，待处理集合不延长文字视图生命。

主聊天的真实 UIView/SwiftUI 内容、现有 offset、阴影、圆角、侧栏渐显与 24pt 层次位移保持原代码。AppModel 既有流式展示暂停继续使用；没有暂停模型接收、回答完成、聊天切换、导航确认或原生滚动状态同步。Markdown 解析与测量方法未修改。

## 已有方案和历史区别

当前已有 equatable 聊天宿主、收尾进度在叶子消费、流式展示暂停及选字手势归属判断；不能据此推断整个正文已经完全冻结。当前右侧移动仍为 SwiftUI offset。DrawerTrackedContentLayerMotion 操作的是左侧内容层，不能误认为右侧 mainHost。

保存的 4846/4847 源码确实做过 UIHostingController 承载真实聊天、mainMotionView.transform 移动和原生运动接管；历史材料有装机证明，未找到足以认定性能通过的验收。4837–4839 的截图覆盖是另一条曾被拒绝的路线，历史反馈为正文不同步和首次触摸迟滞。4848 改掉渐显和层次位移后被拒绝，也不能据此否定 UIKit 运动本身。

Apple 的 [UIView.transform 文档](https://developer.apple.com/documentation/uikit/uiview/transform)说明变换不影响 Auto Layout；它没有给整个界面零渲染成本的保证。[Observation 文档](https://developer.apple.com/documentation/SwiftUI/Managing-model-data-in-your-app)说明 body 对模型属性的读取会形成更新依赖。直接移动 UIView 与暂停这些依赖的内部工作是不同的改动。

- Generic iOS Release 编译通过（388.55 秒，未签名）；App 与扩展均为 1.0 / 5019、arm64。完整编译与产物身份以 `work/verification/drawer-viewport-freeze/build-result.json`、`artifact-receipt.json` 为准。

## 实机验收与限制

原生系统是否在实际拖动时反复发出同值通知，目前没有频次证据。若原本就很少，收益可能很小；准备横向绘制范围还可能把一次绘制移到较早的时刻，因此首帧也要比较。合并不等于零绘制或零 Markdown 更新。

在 iPhone 17 Pro 对比 5018 与 5019，分开记录按住左右往返和松手收尾：空聊天、长正文、侧栏打开时换到长聊天再关闭、流式回答、带键盘拖动。检查文字无缺画、第一下滚动/点击正常、选字正常、正文与标题同步、视觉样式不变。Air 若另测，单独记录，不混用设备结论。

任何缺画、跳动、首帧恶化或无明确收益，都可关闭实验或回到 5018；没有实机结果前不把它并入已验收版本。本轮没有启动模拟器、访问聊天容器或安装手机。
