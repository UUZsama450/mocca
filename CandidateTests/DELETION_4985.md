# 4985 删除消息视口交接候选

本候选基于已部署的 4984，来源为 `mocca-orphan-chat-ownership-4982-a` 的实际文件（含其未提交的聊天归属修复），其底座为 clean 4957 选定继承链。逐文件清单见 `work/verification/baseline-4984-source.json`。本轮产品差异仅 RootView.swift 与构建号；消息存储、归属、折叠、Markdown 等其他 40 个产品 Swift 文件一致。

## 问题与证据边界

4984 的普通删除保护要求上一条用户消息有当前 revision 的可见 frame。长助手消息覆盖视口时，这个条件往往不成立，直接走模型删除。另一条尾删路径仅接受“最后一条助手、紧邻用户、近底但不在底部”等狭窄条件，且会把末尾 1–2 行挪到另一个 eager 分支再移回。两条路径均等待几何稳定的轮询，不向 iOS 18 ScrollPosition 显式申请删除前释放。

`work/handoffs/mocca-4957-phone-backroom-2026-09-03/phone-console-recovered.log` 是同基座历史实机证据，记录的是删除后切出再切入的空白和 native.geometryCorrection，支持检查真实内容与底部控制交接；它不是本次 4984 直接删除的匹配运行时证明。未把 4961–4976 其他候选结果当作当前版本根因证明。

## 改动

- 非流式、当前聊天、无用户滚动的删除先暂停旧跟随，向当前 native modifier 提交 request ID。
- iOS 18 modifier 清除保留的程序滚动语义；下一次主队列交接确认后，才执行模型删除。iOS 17 不需要释放 ScrollPosition。
- 保留可见的上一条用户消息位置；否则优先其他可见存留行，再选择真实邻接消息 ID。删除后不要求离屏锚点先自行产生 frame。
- 更新后的视图接受至多一条定位命令：已测得当前 revision 的可见锚点走原生合法范围修正，否则向真实消息 UUID 发一次无动画 scrollTo。不会定位到透明 bottom sentinel。
- 离屏目标统一落在上方，避免把真实消息放到覆盖式输入框背后；可见锚点选择和完成判断排除输入框遮挡区。
- 完成依据真实目标行可见；完成事件不补写、不重试。用户拖动、导航、切聊天、键盘和新删除可取消旧视口工作。
- 明确点击的删除不会因为视口取消而丢失。提交前取消会执行该模型命令一次，提交后取消不再执行，过期回调不处理新请求。
- 删除旧的尾部 eager 分支、两个 20 次轮询和距离补偿路径。RootView 新增 249 行、删除 555 行，净减 306 行。

这是一条删除路径替换，不是统一滚动内核，也没有移入未实装的 4958 折叠候选。

## 验证

`/usr/bin/python3 CandidateTests/check_deletion_handoff.py` 提取产品实际请求类型、选择、入口、提交、修正、完成与取消方法运行；模拟几何和模型接口。28 项行为检查与 24,576 组存留集合检查通过，覆盖不可见前驱、快速连续删除、单条/全部版本标记、取消前后恰好执行一次、过期回调、一次写入、空聊天与合法 offset。

此测试不模拟 SwiftUI 懒加载，不证明真机滚动视觉。4984 聊天归属的 22 项检查通过。Swift parse 与 diff check 通过。签名 Release 和部署结果将在装机后记录于 `work/verification/result.json`。

## 手机验收

1. 长聊天里，在长助手回复末尾连续删除多条（上一条用户气泡不在屏幕内），确认删除生效、出现真实邻接消息、无需滑动救回。
2. 上一条用户气泡可见时删除，检查阅读位置；分别覆盖中段、真实底部、近底与历史窗口。
3. 删除单个版本与全部版本，确认数据行为一致；快速连续删除、删除后立即拖动/切聊天，检查无旧回调回拉。
4. 确认普通流式、键盘、侧栏以及原有代码折叠行为无回归。

一个取舍是：删除整屏长消息且没有可见存留锚点时，会定位到真实邻接消息，不尝试保留已经不存在的内容坐标。若目标行没有出现，可用已有 `-diagnoseChatBottom` 入口采集匹配操作日志，不继续叠延时/重试。普通启动未开启此高频诊断。
