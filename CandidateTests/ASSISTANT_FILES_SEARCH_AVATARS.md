## 文件功能

助手设置的「提示词」后增加「文件」。每个已保存的助手可新建、批量导入、查看及编辑 Markdown、重命名、导出、删除和恢复上一版。新助手先保存身份，再进入文件管理。

文件内容保存到对应 AssistantProfile 的独立 `files` 字段，现有原生设置备份随 Profile 编码带上该字段。文件不是聊天附件，不改写已有记忆。导入复制完整 UTF-8 文本，不保留外部 URL 或持续访问权限；支持 `.md`、`.markdown` 和 `SKILL.md`，不支持技能压缩包或执行脚本。每份上限 64 KiB，每位助手最多 32 份，当前正文合计 256 KiB；超限明确拒绝，不静默截断。

「聊天时使用」和「允许助手编辑」分别设置。新导入默认使用、禁止助手编辑。启用的完整正文按稳定 JSON 编码加入该助手每轮请求，包括新聊天、重生成和群聊轮到该助手发言时；文件名和正文不能修改 App 持有的权限。启用文件会占用请求上下文，并发送给用户选择的模型服务。模型不支持工具时仍会收到启用文件，但无法调用文件编辑工具。

文件独立保存，外围助手设置保存保留实时文件列表。所有写入先读取实时助手并校验文件集合与总大小；更新、删除和撤销现有文件时同时核对 revision。持久化成功后才发布给界面。批量导入整体成功或整体失败。同文件的过期编辑、删除和撤销都拒绝覆盖；其他助手和其他设置不受文件提交影响。

助手工具只接受文件 UUID、预期版本和完整正文，不提供创建、删除、重命名或更改权限接口。请求开始时的读写范围与提交时的实时启用／编辑权限均须通过。提交还检查该回复的 run ID、message ID、会话存在性和任务取消状态；关闭权限、取消回复或删除文件后的迟到操作会失败。保存失败返回明确失败结果。

每次正文或文件名改变保留一份上版快照；恢复后消耗该快照并继续增加版本号。恢复不恢复旧权限。详情显示修改者、时间和版本。用户输入未保存时不会被自动覆盖；发现其他修改会显示冲突并保留草稿供复制或导出。

旧版本不会随编辑次数累积。当前限制下，每位助手的全部旧版正文最多 32 × 64 KiB = 2 MiB，加上当前正文最多 256 KiB，共最多 2.25 MiB 的 UTF-8 正文；实际编码另有 JSON 转义与元数据开销。删除文件同时移除它的上版快照，没有文件回收站。导入源文件、此前已导出的备份及已存在的聊天／工具记录不受此操作影响。删除作用于当前助手文件数据。

## 搜索头像

搜索结果使用实际用户头像及消息发言助手的头像。单聊的旧记录在缺少作者标识，或作者标识是已知的旧存储占位值时，使用所属助手；群聊按消息作者识别。明确记录了作者但该助手已不存在时，显示中性默认头像。搜索不会按当前选中的助手猜测归属。原来的 20 pt 位置、标题和摘要布局保持一致。

仅挂载的搜索行请求头像。用户 JPEG 的缓存键每次搜索计算一次；自定义图片在串行后台队列通过 ImageIO 缩到实际显示像素，不在行 body 读取文件或解码。相同 key 共享在途请求；缓存设置为 64 项、2 MiB 成本目标，并缓存失败结果以免反复读损坏文件。缓存限额是系统管理目标，不是实际常驻内存或严格硬上限。App 保存头像使用新的文件名，用户 JPEG 使用内容摘要，因此换头像会使用新 key。

查询变化或离开搜索时会取消视图消费；已经排队的共享解码可完成并填入缓存，取消或换 key 的旧视图不能发布结果。没有全助手预热、网络图片请求、常驻计时器或逐帧头像工作。既有搜索防抖、取消、范围、命中版本与文本扫描路径保持不变。
