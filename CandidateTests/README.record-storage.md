# 4979 聊天记录保存优化

基于隔壁 `mocca-4977-storage-save-a` 的候选，4978 已改为按记录保存；4979 进一步消除每次重开后首次保存时对大备份的完整解码。相对 4978，只改存储实现和构建号，发送时序、网络、界面、动画、键盘、滚动及助手逻辑没有新增改动。

## 最终机制

- 主存档和独立上一版备份都按变化记录更新；备份直接读取持久化的变更记录，日常不解码或保留整份备份消息对象。
- 去掉重复的库内上一代恢复及内存编码差异缓存，保留一条独立完整备份恢复路径。
- 初次导入/从 4978 升级时，在初始化阶段做一次全量对齐；后续重开只加载主存档，首次发送也做小量更新。
- 发送仍以保存成功为网络请求前提。正常流式结束沿用异步保存；停止/失败分支沿用同步契约。正在变化的一条消息按整条保存，旧消息正文不跟着重写。
- SQLite 事务、身份减少保护、校验、失败拒绝、旧格式保护标记及原有导出/附件规则保留。读取备份恢复时仍全面验证；不会每次提交都全面扫描未改动的备份记录。

详细边界见 [设计](RECORD_STORAGE_DESIGN.md)；冷启动问题及测量见 [记录](COLD_START_FINDINGS.md)。目录和分支沿用 4978 名称，最终产品构建号为 **4979**。

## 验证

最终 hosted XCTest **18/18 通过**，覆盖冷重开、删除/重排/重加、流式完成后下一条发送、迁移、旧格式导出、字段完整性、流式冷启动清理、事务失败/重试、竞争写者、新于主库的备份拒绝、腐坏恢复和未来版本拒绝。

500 条合成消息的真实进程中断实验通过：提交前退出后重开全部为旧记录；提交后退出后重开全部为新记录。退出行为只存在于独立 DEBUG 故障副本。实际 4978 和 4979 存储代码交替读写的兼容测试通过，未修改记录保持字节一致。

同一 x86_64 iOS 26.2 模拟器，4800 条 / 45.42 MB 合成存档，优化编译、交替独立进程重开三轮的中位数：

| 指标 | 4978 | 4979 |
| --- | ---: | ---: |
| 日常启动加载 | 641.04 ms | 630.51 ms |
| 重开后第一次保存 | 651.52 ms | 27.03 ms |
| 第二次保存 | 19.54 ms | 18.98 ms |

上述冷重开不含一次性升级准备。Hosted Debug 连续保存第 3–6 次中位数：大存档隔壁编码缓存候选 512.18 ms、本版 49.78 ms；小存档分别 6.97 ms、10.65 ms。小存档多一份耐久事务仍有固定开销。原始数据均保留于 `work/verification/`。

## 装机及验收边界

主 App 与扩展均为 0.1.0 (4979)，arm64 Release 构建、严格签名、描述文件及 dSYM UUID 已核验。装机/启动/版本回读以 `work/verification/*4979*` 最终结果为准。

模拟器测试和成功装机不能保证 iPhone 17 Pro 的交互已经完全不卡。保存仍有身份遍历、值比较和小型同步事务；长文本最终解析/排版等独立成本仍存在。没有复制手机聊天存档，因此不提供装机前后聊天字节或语义一致性快照证明。
