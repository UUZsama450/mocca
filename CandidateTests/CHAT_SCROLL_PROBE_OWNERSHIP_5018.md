# 5018：聊天滚动探针的登记与交接

基线是 5017 / `2fead31c01b334f13a5a5f9bf549d69850dc176e`。本候选延续 5016 的关闭动画复用、5017 的 scrollsToTop 幂等写入。

旧探针与新探针遇到同一个 UIScrollView 时，旧探针拆卸会撤销新登记；已排队的旧 resolve 也可能在拆卸后重新绑定。这是源码及可控生命周期复现确认的缺口，尚未证明是手机侧边栏卡顿的原因。

修复把弱引用盒、原生滚动门禁和状态栏 delegate 合并为同一份 ChatScrollViewRegistration 所有权。新登记先接管，再释放旧登记；旧主人只能撤销自己的登记。较早创建的探针不能抢走较新探针仍然持有的绑定，但较新的绑定释放后，尚未拆卸的旧视图可以通过一次新的解析请求重新登记。

排队解析按 generation 失效，并合并同一代的重复调度。真正 dismantle 是终点，临时离开 window 可以恢复。每次刷新检查当前最近的 UIScrollView 祖先；不继续信任过时的祖先缓存。原始 UIKit delegate 的转发与恢复实现保持不变。

## 验证

- `check_chat_scroll_probe_ownership.py`：从真实源码提取声明，5018 的 20 个场景全部通过；5017 在其中 13 个场景重现预期缺口。覆盖同/不同原生宿主、共用/独立盒子、旧回调、临时离窗、祖先更换、销毁及重新登记。
- `check_drawer_close_driver_reuse.py`：5018 的 26 个关闭状态场景通过；5015 的 6 个已知旧问题按预期复现。
- `check_drawer_scroll_top_idempotence.py`：两个版本共 80 项状态检查通过。控制性重复登记/重置 100 次时，scrollsToTop 写入由旧版 100 次保持为 0 次；外部漂移仍修复一次。这不是实测一次手势的调用量。
- 三项都使用可控 UIKit/调度接收器。真实触摸、SwiftUI 生命周期时序、帧率、键盘及长聊天交互尚未实机验收。
- 完整 Generic iOS Release 编译通过（388.28 秒，未签名）；App 与扩展均为 1.0 / 5018、arm64。产物身份记录见 `work/verification/chat-scroll-probe-ownership/`；以 `build-result.json` 与 `artifact-receipt.json` 的最终结果为准。

产品改动只在 RootView 的弱引用盒、原生门禁、探针登记区域，以及项目版本号。AppModel、Markdown 渲染、聊天存储及动画公式均保持基线内容。新增代码承担所有权和生命周期职责，不是仅靠增加延时或重试。
