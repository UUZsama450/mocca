# 5016：关闭侧边栏时保留正在执行的动画

基线：`bf5865d390dfffba0a45fc13e9cbd3db8335a662`（审阅包对应的 1.0 / 5015）。
候选：`work/candidates/mocca-drawer-close-driver-reuse-5016-a`，分支 `codex/drawer-close-driver-reuse-5016`。

## 问题和修复

正常关闭先启动目标为 0 的 display-link 动画，再由现有的 9 ms 延迟任务发布
`isDrawerPresented = false`。原来的观察回调只判断 detached 通道是否活跃，
因此会把自身的关闭通知当作外部打断，取消并重新启动同方向的动画。
重启会改变 sequence、起始时间和初始速度，虽然采样位置能衔接，弹簧阶段却被重置。

现在当 detached 通道活跃、驱动器已经朝 0 关闭、没有活跃手势、没有待接管的
会话关闭请求时，观察回调保留当前驱动器，继续同步原生滚动开关。
朝 1 打开时的外部关闭、没有活跃驱动器的 detached 状态，以及有手势或待处理
会话请求的情况仍执行原来的接管流程。

产品逻辑仅修改 `RootView.swift` 中这一处观察回调。App 和扩展的四处版本号改为
5016。弹簧参数、9 ms 任务、取消和 sequence 校验、打开时的滚动锁交接顺序、
完成回调、流式显示恢复和视觉修饰保持基线实现。
