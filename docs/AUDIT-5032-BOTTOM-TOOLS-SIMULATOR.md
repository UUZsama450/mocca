# 5032 工具内部转场：模拟器对照测量

2026-09-14。用户暂时不方便操作手机，改为模拟器测量。本轮没有启动真机录制，没有修改 5032 产品代码、安装包或手机数据。

## 结论

在隔离的模拟器宿主里，**进入非空指令页时，列表创建、图更新和布局产生了可重复的集中主线程工作**。相同二进制只将测试指令数量从 8 改为 0，三次重复的最长主线程非等待区间由 35.30–39.22 ms 缩短到 9.00–9.39 ms。更多工具和上下文的进入对照没有相同幅度的变化。

这定位了指令页的一项开销，但没有证明它就是手机反馈的全部原因。上下文页没有出现同样的长区间，不能把两页都归因于指令列表，也没有证实真机 120/60 Hz 差异。本轮未实施性能修复。

## 测量范围

- 独立 Bundle ID：`com.mocca.local.tools-motion-5032`；iPhone 17 Pro 模拟器，iOS 26.2，Intel Mac，报告最大刷新率 60 Hz。用户真机为 iOS 27.0 / A19 Pro / 120 Hz，绝对时间不可直接迁移。
- 整份当前 `BottomToolsSheet.swift` 原样复制进 `-O -g` 宿主，SHA-256 为 `48bea7fe74da653e841f19fa576a4abb9b9e36854f8f7a3c71f68088c1e15068`。实际页面、条件分支、动画、detent 和导航方法均来自该文件。
- 外部 AppModel、服务、设置页及聊天背景使用隔离替身与合成数据。因此测量不覆盖完整 App 的观察依赖、真实聊天布局、流式更新或网络负载。
- 自动调用真实 `open` / `back`，不包含手指触摸和按钮命中分发。未加入 display link、逐帧日志、逐步画面标签或父级 route 观察器。启动握手轮询在测量开始前结束。
- 每组执行四轮、共 24 次导航，两个子页顺序交替。第一轮单独标记；后续每个方向三次重复用于下表。Time Profiler 按模拟器设备和确切进程附加，两个有效 run 均成功结束、完整导出。
- 8 条与 0 条对照使用相同可执行文件，仅启动参数 `--instruction-count` 不同。它改变非空列表与空占位分支，也改变相应数量状态，不能由此断言某一个 SwiftUI 函数独自致因，或全部八行都被立即创建。

## CPU 与 run loop 结果

单位均为毫秒；每格为三次重复的中位数。

| 方向 | 8 条：主线程采样总量 | 0 条：主线程采样总量 | 8 条：最长非等待区间 | 0 条：最长非等待区间 |
| --- | ---: | ---: | ---: | ---: |
| 根页 → 更多 | 141 | 135 | 31.06 | 30.42 |
| 更多 → 根页 | 156 | 160 | 19.06 | 14.45 |
| 更多 → 指令 | 60 | 38 | **35.50** | **9.36** |
| 指令 → 更多 | 71 | 34 | 8.16 | 5.44 |
| 更多 → 上下文 | 42 | 41 | 13.15 | 15.41 |
| 上下文 → 更多 | 38 | 42 | 6.98 | 6.82 |

“主线程采样总量”是实际观测窗口内 Running 状态的采样权重累积，窗口实际约 755–805 ms；它不是单帧耗时，也不是动画完成时间。“最长非等待区间”是主 run loop 离开 waiting-for-events 到再次进入的墙钟跨度，可能包含调度或其他等待，不等同于呈现帧超时。不能把更多工具较高的累计总量理解为它一定更卡。

非空指令进入的三个最长区间为 35.50 / 35.30 / 39.22 ms；其中分别有约 36 / 35 / 39 ms 的 Running 采样权重，采样分辨率约 1 ms。这支持这些特定区间内存在连续 CPU 工作，而不只是空等。堆栈包含 `GraphHost.flushTransactions`、AttributeGraph 更新、`_LazyLayout_Subviews.apply`、`_PaddingLayout.sizeThatFits`、`LayoutEngineBox.sizeThatFits` 和 `CA::Transaction::commit`。布局、图更新与提交的 inclusive 归类互相重叠，不能相加。

指令返回的累计工作也减少，但原来的返回路径没有同样的 35–39 ms 长区间；尚不能据此解释手机关闭动画的感觉。上下文进入仍约 13–17 ms 的模拟器区间，缺乏与指令相同的证据。

## 有效性与画面检查

- 每个有效 CPU run 有 22 个可对齐的开始 signpost，时钟拟合最大残差分别小于 0.072 ms 和 0.043 ms。录制命令显示“Starting recording”并不保证采样覆盖已经开始；首轮根页→更多、更多→上下文缺少完整 signpost 对，因此明确排除，没有记作零开销。两组各 18 个后续观测窗口均有效。
- Running profile 样本与原始 TimerFired 记录逐项校验；权重单位通过原始格式确认。250 ms potential-hangs 表有效但为空，它无法排除更短的动画卡顿。Time Profiler 本身有采样成本，宿主后台负载也会变化。
- 独立干净视频包含 391 个实际解码样本，逐项核对了全部 24 次导航的页面与方向。可见根页↔更多伴随弹层高度变化；子页返回的中间画面仍保留退出内容。未从这些样本确认深层页面独有的空白或瞬移。
- 录屏是可变帧率且有稀疏/缺失样本，不能把编码 PTS、画面变化数或请求截图时间当成屏幕实际出帧。因此不报告 FPS 或据此判定高刷。
- `video-baseline` 为试录，短暂与分析器编译重叠，已排除性能比较。首次 `cpu-profile` 因默认连接 Mac 而未找到模拟器 PID，退出 21，属无效录制；有效结果来自指定模拟器设备的 `cpu-simulator` 与 `cpu-empty`。视频早期按数量自动关联的临时输出也已弃用，采用逐项复核后的 `video-analysis-reviewed`。
