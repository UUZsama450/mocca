# 5038：侧栏接管期间在原生外层分配触摸

## 基线与范围

从 17 Pro 现场读回的测试包 **1.0 (5036)** 对应提交 `06911104abb3c10d599d0ca2137849aa0d4ef683` 创建分支 `codex/drawer-native-hit-routing-5038`。142 个构建输入与原部署清单一致，保留 5036 安装产物作为回退参考。正式包为 5029。

旧 5033 快速反向记录中，六段较重更新采到了新触摸、聊天宿主命中检查与响应图更新。本候选验证一个具体假设：当现有侧栏交互门已经接管聊天面板时，可以在原生外层回答触摸归属，减少进入正文宿主的查询。旧记录没有证明六段均发生于此门开启期间，因此不能预先承诺覆盖全部重更新。

## 实现

- 稳定的透明 `DrawerMainPanelTouchShield` 作为真实聊天宿主的兄弟视图，与宿主使用相同的尺寸和原生位移。
- 严格沿用已有 `isInteractionBlocked` 条件。接管期间，聊天面板内的点交给轻量触摸层；露出侧栏的点返回 nil，继续向侧栏分配。
- 触摸层调用原有关闭回调；现有上层拖动手势继续负责方向判断与动画交接。
- 解除接管时，触摸查询恢复原来的 `super.hitTest` 路径。正文宿主及其本地状态始终保留。
- 视觉遮罩、圆角、阴影保留原样。新路径开启时，原 SwiftUI 遮罩不再重复承担触摸接收。
- 启动参数 `-disableDrawerNativeHitRouting` 关闭候选路径，用同一二进制对照；它与旧的 live-host 对照开关独立。

没有改变 `RootView` 手势/收尾函数、`drivesDrawer` 发布、正文渲染、键盘逻辑、存储或迁移。产品差异集中在 RootView 的宿主/外观辅助类型，以及四个构建号。

## 验证与接受条件

证据目录：`work/verification/drawer-native-hit-routing-5038`（主 checkout 下）。

1. 源码提取的 UIKit 检查使用原有遮罩/contentShape/clipShape 与真实 SwiftUI 宿主；同一宿主在原/新 wrapper 间复用，对照命中范围、正常路径身份、恢复后的第一下，以及不同尺寸和位移。
2. 整 App UI 开关对照检查文字聊天侧栏行的一次点击、遮罩的一次点击、关闭后的输入与软件键盘、空聊天反复左右拖动。该用例等候稳定端点，不能冒充动画未结束时重新落指的快速反向验收。
3. 真机接受条件：5036 对照与候选在同一文字/空聊天场景下，重新落指相关长帧减少；侧栏纵向滚动、长按选字、链接、键盘、松手反向和界面外观维持正确。当前构建/模拟器证据不能代替此项。

若新路径没有收益，或产生手势/键盘回归，关闭/撤回这一候选；不叠加交接状态修补来掩盖它。

原生命中实现遵循 [Apple UIView.hitTest 文档](https://developer.apple.com/documentation/uikit/uiview/hittest(_:with:)) 的局部坐标、可交互性、边界和返回窗口层级内视图的规则。

当前结果以证据目录内的 `REPORT.md` 为准；本候选未因创建分支而自动部署到手机。
