# 5036：简单回底箭头不再响应跟随过程中的中间距离

基线：已安装并得到键盘／弹层正面反馈的 5035，`e5476cc24fbe147cd24d2f900ba2b130b8796e54`。

## 问题与改动

用户在简单导航模式下观察到：键盘升降时，正文中央短暂出现很淡的回底箭头；流式输出跟随底部时，箭头也会闪现。

原显隐函数收到 `!isNearBottom` 就开启箭头，未区分用户离开底部与底部跟随尚未落地时的中间几何。5036 复用现有的 `shouldKeepNativeBottomPosition`：仍由底部跟随持有位置、也没有后续消息窗口时，不因为该中间距离开启箭头。它统一覆盖键盘布局和流式内容增长，无需增加计时器、任务或逐帧观察。

这个判断只阻止一次错误的“显示”，不提前隐藏已有箭头。准确到达最新底部仍是原来的隐藏条件。真实原生触摸、历史阅读、消息导航、独立发送定位、消息替换、初建聊天从顶部增长及后续窗口等边界，沿用已有归属判断。

产品改动只在 `RootView.swift` 的 `updateQuickReturnToBottomVisibility`，外加主 App／扩展构建号。日志使用原有默认关闭的 `-diagnoseChatBottom` 开关。按钮外观、过渡动画、点击动作、正文滚动、键盘交接、流式处理、发送和存储代码均保持基线实现；其余 140 个 App 文件逐字节一致。

## 验证

完整结果与限制见 验证记录（本地历史材料：`work/verification/simple-arrow-keyboard-5036/VALIDATION.md`）。

- 提取实际产品显隐函数和底部归属判断做受控对照：5035 在键盘、流式中间几何两项失败，5036 的 14 项均通过，包括 60 次内容增长状态变化、手指接管、历史阅读、后续窗口、回底落地和邻近底部滞回。
- 受控状态输入不等于实际流式网络请求或整 App 的流式渲染验收。
- 五类模拟器界面检查均有通过结果：底部与空聊天收放键盘、历史位置与点击回底、键盘打开后主动上翻、工具／模型面板往返。最终三轮键盘复测拦下 3 次中间几何显示请求，没有产生箭头显示状态。
- Debug Simulator 与 Generic iOS Release 构建通过；主 App／扩展严格签名及二进制与 dSYM UUID 核对通过。
